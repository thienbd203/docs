<a name="introduction"></a>
## Giới thiệu

"Contracts" của Laravel là một tập hợp các interfaces định nghĩa các core services được cung cấp bởi framework. Ví dụ, contract `Illuminate\Contracts\Queue\Queue` định nghĩa các methods cần thiết để queue jobs, trong khi contract `Illuminate\Contracts\Mail\Mailer` định nghĩa các methods cần thiết để gửi e-mail.

Mỗi contract có một implementation tương ứng được cung cấp bởi framework. Ví dụ, Laravel cung cấp queue implementation với nhiều loại drivers khác nhau, và mailer implementation được hỗ trợ bởi [Symfony Mailer](https://symfony.com/doc/current/mailer.html).

Tất cả Laravel contracts đều nằm trong [GitHub repository riêng](https://github.com/illuminate/contracts). Điều này cung cấp một điểm tham khảo nhanh cho tất cả contracts có sẵn, cũng như một package duy nhất, decoupled có thể được sử dụng khi xây dựng các packages tương tác với Laravel services.

<a name="contracts-vs-facades"></a>
### Contracts so với Facades

[facades](/docs/{{version}}/facades) và helper functions của Laravel cung cấp một cách đơn giản để sử dụng Laravel services mà không cần type-hint và resolve contracts từ service container. Trong hầu hết các trường hợp, mỗi facade có một contract tương đương.

Khác với facades, không yêu cầu bạn require chúng trong constructor của class, contracts cho phép bạn định nghĩa explicit dependencies cho các classes của bạn. Một số developers thích định nghĩa dependencies của họ một cách explicit như vậy và do đó thích sử dụng contracts, trong khi các developers khác thích sự tiện lợi của facades. **Nói chung, hầu hết các applications có thể sử dụng facades mà không gặp vấn đề trong quá trình phát triển.**

<a name="when-to-use-contracts"></a>
## Khi nào nên sử dụng Contracts

Quyết định sử dụng contracts hay facades sẽ phụ thuộc vào sở thích cá nhân và sở thích của team phát triển của bạn. Cả contracts và facades đều có thể được sử dụng để tạo ra các Laravel applications robust, well-tested. Contracts và facades không loại trừ lẫn nhau. Một số phần của applications của bạn có thể sử dụng facades trong khi các phần khác phụ thuộc vào contracts. Miễn là bạn giữ responsibilities của class tập trung, bạn sẽ nhận thấy rất ít sự khác biệt thực tế giữa việc sử dụng contracts và facades.

Nói chung, hầu hết các applications có thể sử dụng facades mà không gặp vấn đề trong quá trình phát triển. Nếu bạn đang xây dựng một package tích hợp với nhiều PHP frameworks khác nhau, bạn có thể muốn sử dụng package `illuminate/contracts` để định nghĩa integration của bạn với Laravel services mà không cần require Laravel concrete implementations trong file `composer.json` của package.

<a name="how-to-use-contracts"></a>
## Cách sử dụng Contracts

Vậy, làm thế nào để bạn lấy được implementation của một contract? Thực ra khá đơn giản.

Nhiều loại classes trong Laravel được resolve thông qua [service container](/docs/{{version}}/container), bao gồm controllers, event listeners, middleware, queued jobs, và thậm chí cả route closures. Vì vậy, để lấy implementation của một contract, bạn chỉ cần "type-hint" interface trong constructor của class đang được resolve.

Ví dụ, hãy xem event listener này:

```php
<?php

namespace App\Listeners;

use App\Events\OrderWasPlaced;
use App\Models\User;
use Illuminate\Contracts\Redis\Factory;

class CacheOrderInformation
{
    /**
     * Create the event listener.
     */
    public function __construct(
        protected Factory $redis,
    ) {}

    /**
     * Handle the event.
     */
    public function handle(OrderWasPlaced $event): void
    {
        // ...
    }
}
```

Khi event listener được resolve, service container sẽ đọc type-hints trên constructor của class, và inject giá trị phù hợp. Để tìm hiểu thêm về đăng ký things trong service container, hãy xem [documentation của nó](/docs/{{version}}/container).
